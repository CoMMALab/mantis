Watch mantis record an algorithm for one robot. Each step on the timeline is one call the tracer makes. mantis optimizes as it records, so a call either adds a new scalar or node, or is absorbed on the spot: folded to a constant, dropped as a zero product, simplified to an operand it already has, or merged with an identical earlier value. The last step is dead-output elimination, the one optimization that runs afterwards. Drag to pan, scroll or pinch to zoom, click to inspect, and double-click a node to expand it into its scalars.

From graph to schedule

schedule.build turns the optimized graph into work for one problem's warps. It coarsens nodes into tasks (a cheap node with one consumer is recomputed inside it), levels tasks into stages, gives each stage's tasks to the k warps longest first, and puts a barrier only where a value crosses warps. Code generation then splits each warp's 32 lanes into P problems and runs each warp's items of a stage as one statement per expression shape, in passes of 32 / P lanes. Colour the graph above by Task or Stage to see the first two steps; click the chart to see the lanes.

Times are modelled, not measured: an item of c statements is c units, and a shape group of m items takes ⌈m / (32 / P)⌉ passes. Barrier cost, memory latency and occupancy are left out. Scratch and table sizes come from mantis's own code generator (cuda.layout); the shared-memory limits are the RTX A5000's (48 KB per block by default, 99 KB opt-in). Sync mode is __syncthreads; the named and dataflow modes are not shown.

Parallel analysis of the compiled kernel

The metrics of Grama, Gupta, Karypis and Kumar's Introduction to Parallel Computing, applied to the layout chosen above: one problem, run by p lanes. The serial baseline is the thread tier, one lane running every live scalar operation. Everything follows the controls above and the same statement-count model as the chart.

Why E can be low while S is high: one problem on many lanes buys latency, not throughput. When the batch fills the GPU, the thread tier already runs at E = 1 and wins; cooperative tiers pay off when the batch leaves lanes idle. mantis's parallel_analysis computes the same metrics with its own cost model, which still treats ranks as lanes; this section uses the compiled layout instead, so its numbers differ.
